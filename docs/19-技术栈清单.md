## 6. MCP（Model Context Protocol）技术栈

| 项 | 值 |
|---|---|
| 协议版本 | **MCP Streamable HTTP，`2025-03-26`** |
| 报文 | **JSON-RPC 2.0** |
| 服务端实现 | 标准库 `ThreadingHTTPServer`；`POST /mcp`（`initialize` → 响应头 `Mcp-Session-Id` → `notifications/initialized` → `tools/list` → `tools/call`）、`DELETE /mcp`、`GET /health` |
| 客户端 | **框架自带**（`agent/mcp/client.py`，基于 `httpx.Client` 的同步 Streamable HTTP，按 SSE 规范逐行解析 `text/event-stream` 并按 JSON-RPC `id` 匹配响应） |
| 注册方式 | `.lemonclaw/mcp.json` → `{"compliance": {"url": "http://127.0.0.1:8770/mcp"}}` |
| 工具命名 | 注册后为 **`mcp__compliance__<tool>`**（框架一等公民，主 Agent 与工作流 tool 节点均可调用） |
| 关键参数 | `MCP_CONNECT_TIMEOUT=30s`、`MCP_CALL_TIMEOUT=300s`、`MCP_MAX_TOOLS=100`、`MCP_RESULT_MAX_CHARS=20000` |
| 服务标识 | `SERVER_NAME=compliance-officer`、`SERVER_VERSION=0.2.0` |

**为什么用 MCP**：岗位能力全部落在本项目进程内，经底座原生 MCP 通道即可被 Agent 与工作流调用 —— 能力与本项目同生命周期，独立演进、独立单测。

## 8. 认证与安全技术栈

| 项 | 技术 | 参数 |
|---|---|---|
| 口令存储 | **标准库 `hashlib.pbkdf2_hmac`**（PBKDF2-HMAC-SHA256） | 随机 salt，**200 000 次迭代**，Base64 存储；不引编译型依赖 |
| 会话令牌 | **PyJWT 2.15.1**，**HS256** | `JWT_SECRET`（未设置时 jwt/sso 模式**拒绝启动**）；支持令牌撤销水位 |
| 认证模式 | `AUTH_MODE = demo \| jwt \| sso` | 严格分离：demo 内置令牌在 jwt/sso 模式下**必被拒**（实测 401） |
| 权限模型 | **11 项权限矩阵**（`PERMISSIONS`） + 角色 specialist / supervisor / admin | 越权返回 403（实测覆盖） |
| 登录防护 | 按 **(user, ip)** 与 ip 双层退避 | 失败记录 TTL 24 h；`client_ip()` 仅在 `trust_proxy` 可信时采信 `X-Forwarded-For` |
| 企业 SSO | **OIDC Authorization Code + PKCE(S256)** | 严格校验签名 / `iss` / `aud` / `exp` / `iat` / `nonce`；算法白名单；JWKS `alg`/`kty` 一致性；组→角色映射；自动开户；角色变更即撤销令牌 |
| 令牌传输 | **仅 `Authorization: Bearer`**（`X-Auth-Token` 兼容演示） | `?token=` **只对 SSE** 开放（EventSource 不能自定义请求头） |
| 加密库 | **cryptography 50.0.2** + `pycryptodome 3.24.0` | RS256 验签（`PyJWT` 的 RSA 后端）、IdP 密钥生成 |
| 上传防护 | 1 MB 分块读取 + `Content-Length` 提前拒绝 | 防止未鉴权大包打满内存 |

## 17. 关键选型理由（一句话版）

| 选型 | 理由 |
|---|---|
| **能力走 MCP** | 底座对 MCP 是一等公民；岗位能力留在本项目进程内，与流程共用同一套工具，也便于跟随上游更新 |
| **规则/检索确定性，LLM 只做对话** | 合规判定必须可复现、可评测；这直接带来 P7 的 1.00 召回 / 0 误报 |
| **SQLite 单文件 + PG 可选** | 单机一键拉起（试点门槛最低），交付形态再切 PG（本项目自有表下沉，框架运行态不动） |
| **pg8000 优先** | 纯 Python，内网/受限环境免编译；容器与 Windows 行为一致 |
| **rapidocr-onnxruntime** | 模型随包分发、无需外网下载；纯 CPU 推理；中文效果实测可用 |
| **原生前端单文件** | 内网离线、无供应链风险、文本 diff 可审查 |
| **PBKDF2（标准库）而非 bcrypt/argon2** | 零编译依赖，受限环境能装；200k 迭代满足试点强度 |
| **PowerShell 门禁 + JSON 证据** | 每个结论都留可复核的证据文件，而不是"跑过了"的口头承诺 |

## 18. 明确**未**纳入/未验证的技术边界（诚实清单）

1. **真实企业 OA / 合同库 / 邮件网关**：连接器已就绪（`dir`/`http`/`smtp`），但**现场字段名与鉴权未对接**。
2. **贵司 IdP 现场联调**：本机用的是标准 OIDC 实现的本地 IdP（真 RSA/真 PKCE），未接 Keycloak/Azure AD/Okta 实例。
3. **多实例部署**：SSO `state`/一次性 ticket 在进程内存；框架侧运行态共享未做（单实例前提）。
4. **向量检索**：`pgvector` 与 `regulation_embedding` 表已建好但**尚未接入**；当前检索走 keyword-ngram（实测有效，未做 embedding 语义召回对比）。
5. **飞书渠道**：`ENABLE_FEISHU=false`；`ENABLE_BASH_TOOL=false`（安全默认）。
6. **`psycopg[binary]`**：本机安装失败（超时/需编译），因此 PG 驱动走 `pg8000`。
