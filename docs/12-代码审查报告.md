## 4. 关键实测结论（把"猜测"变成"证据"）

### 4.1 `update_state` 是否会提前推进图（审查提出的[待确认]项）

审查怀疑"在 `resume` 之前写 `detail_decision` 会把图提前推进到下一节点"。实测（真实框架 + 真实 run）：

```
next_before : ["specialist_review"]
next_after  : ["specialist_review"]     ← 只写 detail_decision 后仍停在原等待节点
decision_visible: "pending"
```

**结论：不会提前推进**。当前实现（先写非人工字段、再 `resume`）与注释一致，无需改动；
该断言已固化为 `scripts/d0/p4b_decision_binding.py` 的常驻回归项。

### 4.2 决策与节点绑定（防止伪造签核 / 跳过复核）

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 专员对停在主管节点的 run 提交 confirm | 放行，并写入 `supervisor_note`（伪造主管签核） | 409 + `pending_node` 提示 |
| 主管对停在专员节点的 run 提交 approve | 放行，一步办结（跳过主管复核） | 409 |
| 主管在主管节点驳回 | 恒被拒（"角色 supervisor 不允许执行 reject_supervisor"） | 放行并归档 |
| 正常链路 | confirm → 主管通过 | 不变（12/12 回归通过） |

### 4.3 JWT 模式认证姿态（`docs/evidence/auth-posture-jwt.json`，13/13 PASS）

| 检查 | 结果 |
|---|---|
| 演示令牌 + `X-Role: admin` | **401**（修复前 200 = 认证绕过） |
| 账号登录 → Bearer → `/auth/me` | 200，`role=admin`（角色取自令牌而非请求头） |
| 本人改密不带旧密码 | 400 |
| 非管理员改他人密码 | 403 |
| 改密后旧令牌 | **401（立即失效）** |
| 匿名访问 `/diagnostics` | 401 |

## 9. 给使用者的结论

1. **可以放心当作"企业试点系统"使用**：认证（本地账号 + 企业 SSO）、权限矩阵、
   外部系统对接（共享盘 / OA 接口 / 邮件网关）、OCR、并发互斥、证据链、运维入口
   都已按生产口径收紧，且每一项都有**可重跑的回归证据**。
2. **上生产前需要在贵司环境完成的三件事**（都不是"改代码"，而是"填配置 + 验收"）：
   - 选一种合同来源并接入（`docs/13` §2），跑通 P6 的验收口径；
   - 选一种通知通道并接入（`docs/13` §3）；
   - 身份系统按 `docs/15` 接 OIDC（或先用 `AUTH_MODE=jwt` 本地账号过渡）。
   若要走 PG，再按 `docs/16` 装驱动、配 `DATABASE_URL`、跑验收清单。
3. **仍未到生产的部分**已在 §7 逐条列明（工作流运行态仍在 SQLite、多实例互斥、
   Alembic 迁移、pgvector、真库/真 IdP 的现场验收）——这些**不影响单实例试点上线**，
   但必须让使用者知情。
4. **本次修复中最值得注意的五条**（都会被使用者直接感知）：
   - JWT/SSO 模式此前存在**认证绕过**（演示令牌 + `X-Role` 自封管理员）与"大半个 API 401"（现已修复并回归）；
   - 主管"驳回"按钮此前**点了必失败**（现已修复）；
   - 长合同/扫描件/表格抽取失败此前可能被当成"**低风险自动办结**"（现改为强制转人工，并补上了 OCR 与强制转人工两条路径）；
   - 进程崩溃后审批可能**永久锁死**（现有租约 + 启动自愈 + `POST /api/v1/maintenance` 手动释放）；
   - 能力服务此前**启动即崩**（未导入模块），且交付镜像缺三个必需依赖（现均已修复，并补了"服务启动即可用"的回归覆盖）。
