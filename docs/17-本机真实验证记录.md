## 1. 真实 OCR（RapidOCR）

| 项 | 内容 |
|---|---|
| 组件 | `rapidocr-onnxruntime==1.2.3`（含 `onnxruntime` / `opencv` / `numpy`，模型随包分发，无需单独下载） |
| 安装 | `.\.runtime\venv\Scripts\python.exe -m pip install rapidocr-onnxruntime` |
| 验证 | `pytest tests\test_ocr.py -q`（23 项；其中 `TestRealEngine` 3 项是"真的识别出字"的判据） |
| 结论 | **扫描版 PDF（整页位图、无文本层）被真实识别出中文条款**，档位 `ocr_lite`，OCR 文本继续走规则判定并命中 `RR-006`（违约金 50%） |
| 证据 | `docs/evidence/p2-tools-e2e.json`（扫描件一项：`档位=ocr_lite 置信度 0.7 引擎=rapidocr`）、`docs/evidence/d0-g5-ocr-tier.json` |

**实测踩到并修掉的两个真问题**（都写进了代码注释）：

1. **测试件本身没有中文**：PIL 默认位图字体渲染不出中文，导致"引擎看起来不行"。
   已在 `tests/test_ocr.py::_cjk_font` 改为显式加载系统 CJK 字体（simhei/msyh/simsun/STSONG）。
2. **旧断言与升级后语义冲突**：`test_scanned_pdf_has_no_text_layer` 原本用
   `parse_pdf` 的 `char_count==0` 判定"扫描件"，但接上 OCR 后它**应该**有字。
   已改为直接查 PDF 文本层（pdfplumber），并把"OCR 成功"单独断言。

## 2. 真实 PostgreSQL

| 项 | 内容 |
|---|---|
| 组件 | PostgreSQL **16.4**（官方 Windows binaries，解压即用，无需管理员权限、无需 Docker） |
| 位置 | 程序 `C:\co-pg\pgsql`，数据 `C:\co-pg\data`，端口 `55432` |
| 驱动 | **pg8000**（纯 Python，`pip install pg8000` 即可，无需编译） |
| 建实例 | `pwsh -File scripts/pg-local-ascii.ps1 -Action init` |
| 验证 | `.\.runtime\venv\Scripts\python.exe scripts\d0\pg_real_db.py` → **18/18 PASS**（第二次审查后重跑） |
| 证据 | `docs/evidence/pg-real-db.json`（含服务端版本、驱动、表行数、`seq` 序列、断线自愈结果、psql 交叉校验、收尾回收结果） |

**验证覆盖**：建表 → 待办幂等创建 → 原子领取（后到者拒绝）→ 非领取者不得办结 →
审计正序 → 游标不重不漏 → 账号建号与验密 → 令牌撤销水位 → 直接查 PG 确认**本轮**行数 →
**`seq` 严格递增**（同秒事件稳定排序的基础）→ **服务端杀掉连接后自愈** →
**psql 交叉校验**（换一个客户端看同一份数据）→ 收尾回收本轮数据。

**为什么数据目录必须在 `C:\co-pg`**：PostgreSQL 在 Windows 下不转换路径编码，
项目路径含中文会让 `initdb` 报
`invalid byte sequence for encoding "UTF8": 0xcf 0xee`。这是 PG 的硬约束，不是配置问题。

**实测踩到并修掉的四个真问题**：

1. **`rowid` 是 SQLite 专有**：`list_audit` 用它做同秒稳定排序，PG 报
   `column "rowid" does not exist`。已改为显式自增列 `seq`
   （PG `BIGSERIAL` / SQLite `INTEGER PRIMARY KEY AUTOINCREMENT`），业务 ID 由 `UNIQUE` 保证。
2. **老库不会自动加列**：`ensure_schema` 以前有"每进程只跑一次"的缓存，
   老库拿不到新列，调用方撞 `no such column: seq`。
   已改为**每次调用都补列**；且 `ADD COLUMN IF NOT EXISTS` 在 SQLite 上不被支持
   （实测静默失败），因此改为**先查元数据再 ALTER**。
3. **驱动可用性**：`psycopg[binary]` 在本机装不上（超时/需编译），
   因此 `db.py` 的驱动优先级扩为 `psycopg → psycopg2 → pg8000`，三者皆无时明确报错。
4. **连接被服务端断开后不会自愈**（第二次审查·真机重跑时抓到）：
   `_pg_connection` 为省探活开销，在 `PG_PROBE_INTERVAL_S`（默认 30s）窗口内**直接复用缓存连接**；
   而被服务端断开的连接在驱动看来仍是 open（socket 已死），于是窗口内每一次调用
   都拿到同一条死连接并全部失败（实测击杀后端后连续 3 次都是
   `InterfaceError: network error`，业务侧的 `except: pass` 会把失败静默吞掉）。
   现在 `_PgConn.execute/executemany` 判定为**连接级故障**时立即剔除缓存连接，
   下一次调用必定重连；且**只剔除、不自动重试**（网络错误下语句是否已生效未知，
   盲目重试可能把非幂等写入做两次）。该断言（`connection_recovers_after_server_side_kill`）
   已进脚本，18/18 通过。

## 3. 真实 OIDC 单点登录

| 项 | 内容 |
|---|---|
| IdP | **`mock/mock_idp.py`：本地真实 OIDC 协议实现**（真 RSA 密钥、真 discovery、真 JWKS、真 PKCE S256 校验、code 单次使用） |
| 网关配置 | `AUTH_MODE=sso` + `OIDC_ISSUER=http://127.0.0.1:8760` + `OIDC_REDIRECT_URI=…/api/v1/auth/sso/callback` |
| 验证 | `.\.runtime\venv\Scripts\python.exe scripts\d0\sso_e2e.py` → **20/20 PASS**（第二次审查后重跑） |
| 证据 | `docs/evidence/sso-e2e.json`（含 discovery、三段身份映射结果、安全边界结果、审计事件、独立库路径、收尾停端口结果） |
| 数据隔离 | **整轮跑在独立库** `.runtime/sso-e2e/sso-e2e.db`（`LEMONCLAW_DB_PATH`，开跑前删除）——自动开户不再污染演示库，断言也不受库里既有账号影响 |

**验证覆盖**：IdP discovery 与 JWKS → 网关发起授权（PKCE challenge）→ IdP 登录页
（**断言确实渲染出可选身份**）→ 选身份同意（**一次性 ticket**）→ 网关回调换令牌 →
**严格校验 ID Token** → 落地本地账号 → 签发本项目 JWT →
用该令牌访问受保护接口 → **权限矩阵生效**（专员可读规则、不可管账号）→
**三个组分别映射到 specialist / supervisor / admin** → 会话令牌放在 URL **fragment**
（不进服务端日志）→ **安全边界**：authorization code 单次使用、伪造 state 拒绝、
IdP 停用账号后 SSO 不得复活 → **能力服务确实在线** → **审计留痕**。

**实测踩到并修掉的两个真问题**：

1. **审计事件名不一致**：SSO 成功登录在审计库里记成了 `auth.login_success`，
   只有可观测日志里才是 `sso_login_ok`，导致按 `event=sso` 查不到成功登录。
   已修正为按 `via` 区分：SSO 走 `auth.sso_login_ok`，本地账号走 `auth.login_success`。
2. **`urllib` 取不到 302 的 Location**：脚本改用 `httpx(follow_redirects=False)`
   才能可靠拿到回跳地址（否则整条链路在"回跳"处断掉）。

## 4. 复现命令（一键）

```powershell
# 单元测试（6 个模块 166 条：能力服务 / 连接器 / OCR / SSO / 数据库后端 / 审查工具自身）
.\.runtime\venv\Scripts\python.exe -m pytest tests -q -p no:cacheprovider

# 静态审查（含"未定义名称"检查）
.\.runtime\venv\Scripts\python.exe scripts\tools\static_audit.py

# 真实 PostgreSQL（首次需先建实例）
pwsh -File scripts\pg-local-ascii.ps1 -Action init
.\.runtime\venv\Scripts\python.exe scripts\d0\pg_real_db.py

# 真实 OIDC SSO 端到端
.\.runtime\venv\Scripts\python.exe scripts\d0\sso_e2e.py

# 原有全量回归
pwsh -File scripts\d0\run-all-gates.ps1
```

> 说明：本机受限环境会在命令之间回收子进程，因此 `pg_real_db.py` 与 `sso_e2e.py`
> 都设计成"**单次执行内完成起服务 → 验证 → 落证据 → 收尾**"，无需人工驻留服务。
