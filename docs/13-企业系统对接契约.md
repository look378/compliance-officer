# 企业系统对接契约（OA / 合同库 / 邮件网关）

> 面向 **贵司 IT/集成方**。本文写清"小合需要什么、怎么给、给了之后怎么验证"。
> 代码侧实现在 `service/connectors.py`；不改业务代码即可通过**环境变量**切换外部系统。
>
> 默认仍是本项目的 Mock（开箱即用、可跑全部自检）。切换真实系统后，**全部回归依然必须通过**
> （自检里已包含"共享盘目录"这一真实形态的端到端用例，见 `scripts/d0/p6_proactive.py` G 段）。

---

## 1. 一分钟决策表

| 贵司现状 | 选哪种 | 关键配置 |
|---|---|---|
| OA/合同库只能投递到共享盘目录或本地目录 | `CONTRACT_SOURCE=dir` | `CONTRACT_DIR`（+`CONTRACT_DIR_RECURSIVE`） |
| OA/合同库有 REST/HTTP 接口 | `CONTRACT_SOURCE=http` | `OA_BASE_URL`、`OA_LIST_PATH`、`OA_FETCH_PATH` + 字段映射 |
| 内网邮件网关/中台提供发信接口 | `MAIL_GATEWAY=http` | `MAIL_HTTP_URL`（+鉴权头） |
| 有可用 SMTP 账号 | `MAIL_GATEWAY=smtp` | `SMTP_HOST/PORT/USER/PASSWORD/FROM` |
| 演练/离线，不发任何通知 | `MAIL_GATEWAY=none` | — |

> **不会静默回退**：`CONTRACT_SOURCE` / `MAIL_GATEWAY` 写了不认识的取值时，服务**直接报错**。
> 这是刻意的——"以为接了真系统、其实还在用 Mock"是合规系统最危险的失败模式。

## 2. 合同来源

### 2.1 方式 A：共享盘 / 本地目录（最常见，推荐先用这个）

```
CONTRACT_SOURCE=dir
CONTRACT_DIR=\\fileserver\compliance\inbox      # 或 D:\compliance\inbox
CONTRACT_DIR_RECURSIVE=false                    # 需要按子目录归档时设 true
```

目录约定（交给 OA 管理员即可）：

```
<CONTRACT_DIR>/
    合同编号.pdf                ← 原文（支持 .pdf .docx .doc .txt .md）
    合同编号.pdf.meta.json      ← 可选元数据
```

`合同编号.pdf.meta.json`（可选，缺省时按文件名与文件 mtime 推断）：

```json
{
  "contract_id": "OA-2026-1031",          // 可选：覆盖文件名作为合同编号
  "uploaded_at": "2026-10-10 09:00:00",   // 可选：投递时间（用于增量扫描）
  "source": "oa-share"                    // 可选：来源标记，进审计
}
```

行为约定（都有自动化用例覆盖）：

| 场景 | 小合的行为 |
|---|---|
| 目录不存在 / 未挂载 | **判为不可用并告警**（`degraded=true` + 可读错误），绝不当作"没有新合同" |
| 只有 `.meta.json` 没有原文（同步未完成） | 作为**脏数据条目**报出并计入失败明细，提示人工核对 |
| 同一份内容换了文件名 | **不重复审查**（幂等键 = 文件内容 SHA256，与文件名无关） |
| 单个文件读不了 | 该条计入失败明细，**不影响同批其他合同** |
| 子目录 | 默认不递归；需要时 `CONTRACT_DIR_RECURSIVE=true` |

### 2.2 方式 B：HTTP/JSON 接口

```
CONTRACT_SOURCE=http
OA_BASE_URL=https://oa.corp.example
OA_LIST_PATH=/api/v1/contracts/list
OA_FETCH_PATH=/api/v1/contracts/{contract_id}/download
OA_AUTH_HEADER=Authorization
OA_AUTH_TOKEN=Bearer <token>
OA_TIMEOUT_S=15
OA_VERIFY_TLS=true            # 自签证书内网可临时 false（不推荐长期）
```

**字段映射**（贵司字段名不同就改这里，不改代码）：

| 配置 | 默认值 | 含义 |
|---|---|---|
| `OA_LIST_ITEMS_KEY` | `items` | 合同数组在响应里的路径，**支持点号**（如 `data.records`） |
| `OA_ID_FIELD` | `contract_id` | 合同编号字段名 |
| `OA_HASH_FIELD` | `content_hash` | 内容哈希字段名（**可不提供**，小合会下载原文自己算） |
| `OA_TIME_FIELD` | `uploaded_at` | 投递时间字段名 |
| `OA_SIZE_FIELD` | `size` | 大小字段名 |

清单接口期望响应（顺序/额外字段都不影响）：

```json
{
  "count": 2,
  "items": [
    {"contract_id": "OA-2026-1031", "content_hash": "ab12…",
     "uploaded_at": "2026-10-10 09:00:00", "size": 20480},
    {"contract_id": "OA-2026-1032", "uploaded_at": "2026-10-10 09:05:00"}
  ]
}
```

下载接口：`GET {OA_FETCH_PATH}`，返回**原始字节**（PDF/Word/文本皆可），HTTP 200。

失败与结构校验（关键）：

| 情况 | 行为 |
|---|---|
| 返回 HTML 登录页 / 非 JSON | 显式失败：`响应不是 JSON（前 120 字符：…）` |
| 数组字段不在预期路径 | 显式失败并**列出顶层字段名**，方便一眼看出厂商改了字段 |
| 某个条目缺 `contract_id` | 该条标记错误并计入失败明细，其余照常处理 |
| 5xx / 超时 / 连不上 | `degraded=true` + 可读错误；批次不中断 |

## 3. 邮件网关

### 3.1 HTTP 网关

```
MAIL_GATEWAY=http
MAIL_HTTP_URL=https://mailgw.corp.example/api/send
MAIL_AUTH_HEADER=Authorization
MAIL_AUTH_TOKEN=Bearer <token>
```

请求体（小合发给网关）：

```json
{
  "to": "compliance-lead@corp.example",
  "subject": "[主动审查] 合同 OA-2026-1031 已完成自动审查（high）",
  "body": "run_id=…\n风险等级=high\n状态=paused\n待人工环节=specialist",
  "idempotency_key": "review-done:OA-2026-1031:ab12…"
}
```

期望响应：HTTP 200 且 `{"message_id": "..."}`（或 `{"id": "..."}`）。
`idempotency_key` 请在有去重能力的网关上做去重——同一份合同的同一结论不会重复打扰审批人。

### 3.2 SMTP 直发

```
MAIL_GATEWAY=smtp
SMTP_HOST=smtp.corp.example
SMTP_PORT=587
SMTP_USER=compliance-bot@corp.example
SMTP_PASSWORD=<口令>
SMTP_FROM=compliance-bot@corp.example
SMTP_STARTTLS=true
```

邮件头会带 `X-Idempotency-Key`，便于邮件侧审计与去重。
若贵司要求 OAuth2 / 内部中继白名单，请在 `service/connectors.py` 的 `SmtpMailGateway` 上扩展
（约 20 行，改一处即可）。

## 4. 接好之后怎么验证

```powershell
# 0) 看当前生效的连接器配置（不泄露密钥，只回布尔）
curl -s http://127.0.0.1:8790/api/v1/diagnostics -H "X-Auth-Token: local-dev-token" -H "X-Role: admin"

# 1) 只跑连接器单测（含真实 SMTP 协议、厂商字段映射、结构不符必须失败）
.\.runtime\venv\Scripts\python.exe -m pytest tests\test_connectors.py -q

# 2) 跑主动巡检端到端（含"共享盘目录"真实形态：新合同→审查→通知→幂等→脏数据→不可达降级）
.\.runtime\venv\Scripts\python.exe scripts\d0\p6_proactive.py

# 3) 全量回归（必须全绿才允许上线）
pwsh -File scripts/d0/run-all-gates.ps1
```

**验收口径（建议写进验收单）**：

1. 巡检能发现新投递的合同，并**只审一次**（同内容换名不重审）；
2. 外部系统不可达 / 返回结构异常时，系统**告警并停止**，不得静默跳过；
3. 脏数据（有元数据无原文）出现在失败明细里，可被运维看到；
4. 通知确实发出（网关/邮箱可查），且带 `idempotency_key`；
5. 上述 1–4 全部有 `docs/evidence/p6-proactive.json` 作为留证。

## 5. 尚未覆盖、需要贵司确认的事项

| 事项 | 说明 |
|---|---|
| 增量扫描的时间字段 | 目录模式按文件 mtime、HTTP 模式按 `OA_TIME_FIELD`；若贵司时间字段带时区，请统一为 `YYYY-MM-DD HH:MM:SS` 本地时间 |
| 大文件 | 单份合同按内存读取处理；若常见 >100MB，请告知，我们改为流式落盘 |
| 并发/限流 | 巡检默认串行逐份处理；贵司接口有 QPS 限制时请给出阈值 |
| 合同编号唯一性 | 幂等键是小合自己算的内容哈希；若贵司要求以**业务编号**为幂等依据，请说明（涉及"同一编号内容变更"如何处置） |
| 敏感信息 | 合同原文仅在本项目 `.runtime/` 与工作流状态中处理，不外传；如贵司要求脱敏后再入库，请给出脱敏规则 |
