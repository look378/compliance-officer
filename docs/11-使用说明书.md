# 使用说明书 · 合规官「小合」

> 读者：使用者（合规专员 / 合规主管 / 管理员）、评审人、接手开发的工程师。
> 结论先行：**本项目是"可演示、可评测、可审查的完整闭环"，不是可直接上线的企业生产系统**。
> 生产化差距见第 8 节，逐条标注了现状与改造点。

---

## 1. 它是什么 / 不是什么

**是什么**：一个岗位化的合规审查数字员工。你把合同丢给它，它自动解析条款（含表格）、检索法条、
按规则表标注风险、低风险直接出报告、中高风险转人工签核，并把全过程写成可追溯的证据链；
人工驳回的原因不会被直接写成规则，而是生成"规则提案"，经主管批准后版本化入库，下次自动命中。

**不是什么**：

| 误解 | 实际情况 |
|---|---|
| 能替代合规人员做最终判定 | **不能**。AI 结论仅供参考，`high`/`mid` 风险一律要人工确认，报告里带免责声明 |
| 能看懂扫描件 | **目前不能**。当前档位为"无 OCR 模式"，扫描件会被标记低置信度转人工 |
| 能对接你的真实 OA / 邮箱 | 目前接的是 Mock 服务，真实对接点已在代码中标注 `TODO[生产对接]` |
| 打开就能给全公司用 | 认证是演示令牌、无账号体系、数据库默认单机 SQLite，见第 8 节 |

## 2. 快速上手（本机，约 1 分钟）

### 2.1 首次准备（只做一次）

```powershell
cd D:\Project_Experience2.0\项目三\compliance_officer

# 装运行时依赖（含框架依赖 + 本项目依赖）
pwsh -File scripts/d0/install-runtime.ps1

# 部署挂载点：技能包 + MCP 配置 + .env（含 LLM key 注入）
pwsh -File scripts/deploy-runtime.ps1 -EnableMcp
```

> `.env` 里的 DeepSeek key 由部署脚本从既有项目读取；若没有可用 key，请在
> `.runtime\.lemonclaw\.env` 中填 `OPENAI_API_KEY`。

### 2.2 日常启动 / 停止

```powershell
# 启动（三个服务：能力服务 8770 / Mock 外部系统 8780 / 网关 8790）
pwsh -File scripts/start-demo.ps1

# 浏览器打开工作台
start http://127.0.0.1:8790

# 停止
pwsh -File scripts/stop-demo.ps1
```

启动脚本会自检三个服务的健康状态；已运行的服务会跳过。

## 3. 界面使用（工作台）

打开 http://127.0.0.1:8790 后：

右上角三个控件决定"你是谁"：

| 控件 | 说明 |
|---|---|
| 令牌 | 演示令牌 `local-dev-token`（企业版应换成 JWT / 账号体系） |
| 角色 | 合规专员 / 合规主管 / 管理员 —— 决定待办可见范围与可执行动作 |
| 操作人 | 会写进审计链，用于"谁批的"追溯 |

### 3.1 合同审查台

1. 点「低风险 / 中风险 / 高风险」示例按钮一键填充，或直接粘贴合同文本；
2. 也可以上传文件（支持 `.pdf` / `.docx` / `.txt` / `.md`）；
3. 点「发起审查」。

返回内容包含：整体风险等级、run_id、当前状态、若转人工则显示等待哪个角色、
逐条风险条款（命中规则编号+版本、匹配片段、依据法条、修改建议）、未触发风险的条款、完整 JSON。

**预期结果**：

| 输入 | 结果 |
|---|---|
| 无风险条款的干净合同 | `已办结`（低风险自动归档，不惊动任何人） |
| 含"违约金 50%"等中风险条款 | `等待人工`，停在**合规专员** |
| 含保本收益 / 最终解释权 / 无条件解除 / 超时工时 / 免同意收集个人信息 | `等待人工`，停在**合规专员**（后续需主管签署） |
| 扫描件 PDF | 提示未提取到文本，需转人工（当前无 OCR） |

### 3.2 待办审批

- 「待处理」列出当前角色名下待办；管理员可看全部。
- 合规专员动作：**确认**（提交主管复核）/ **要求重标注**（重新判定后回到自己确认）/ **驳回**（终止并生成规则提案）。
- 合规主管动作：**通过归档** / **驳回**。
- 每次审批都会写审计事件，并完结对应待办。

> **只有一次生效**：如果两个人同时点同一个待办，后到者会收到「该审批已被 XX 处理中，请勿重复提交」。

### 3.3 运行概览

- 按状态筛选（全部 / 等待人工 / 已办结 / 异常），或按 run_id 精确查询；
- 点「详情」看该次审查的**完整审计链**：提交、待办创建/认领、人工决策、重新标注、归档，逐条带时间与操作人；
- **系统自愈与诊断**（管理员）：
  - 「释放过期审批占用 + 清理过期令牌」= 调 `POST /api/v1/maintenance`。用于某次审批因进程崩溃留下占用、
    导致该 run 一直提示"已被他人处理中"时**不重启即可自愈**（启动时也会自动清理一次）；
  - 「查看诊断详情」= 调 `GET /api/v1/diagnostics`：编排器与岗位能力服务就绪度、员工运行时就绪度、
    僵尸审批占用清单、日志文件大小与轮转情况、配置问题清单。

### 3.4 规则库 / 规则提案

- **规则库**：列出全部规则（编号、版本、状态、等级、匹配模式、法条依据、来源、批准人），顶部显示规则表指纹；
- **规则提案**：人工驳回后产生。主管可在此**批准**（写进规则库并升版本）或**驳回**。
  同模式但等级不一致的提案会标记为「冲突待裁决」，**禁止直接写入**。

> **决策必须与"当前等待的环节"匹配**：run 停在「专员初审」时只有专员能下确认/重标注/驳回；
> 停在「主管复核」时只有主管能通过/驳回。跨环节提交会被拒绝（HTTP 409），
> 界面会提示"请联系对应的审批人处理"——这是防止**跳过主管复核**与**伪造签核痕迹**的强约束。

## 4. 典型作业流程（按角色）

```
业务方提交合同
      │
      ▼
[自动] 解析 → 检索法条 → 规则标注 → 分级
      │
      ├─ 低风险 ──────────────→ 自动出报告 → 归档
      │
      └─ 中/高风险 → 合规专员待办
                        ├─ 确认 ──→ 合规主管待办 ──→ 通过归档 / 驳回
                        ├─ 要求重标注 → 重新判定 → 回到专员确认
                        └─ 驳回 → 生成规则提案 → 主管待办
                                                    ├─ 批准 → 规则库升版本 → 同类条款自动命中
                                                    └─ 驳回 → 提案归档（规则库不变）
```

## 5. 接口使用（供系统对接）

统一前缀 `/api/v1`，需要请求头：

```
X-Auth-Token: local-dev-token
X-Role: specialist | supervisor | admin
```

> `AUTH_MODE=jwt` 时改用 `Authorization: Bearer <token>`（由 `/api/v1/auth/login` 获取）。
> 该模式下**演示令牌一律无效**，且角色完全取自令牌，请求头 `X-Role` 不再被信任。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/contracts` | 提交合同（JSON：`text`） |
| POST | `/api/v1/contracts/upload` | 上传文件（multipart：`file`；≤20MB，仅 .pdf/.docx/.doc/.txt/.md） |
| GET | `/api/v1/samples` | 示例合同（低/中/高） |
| GET | `/api/v1/pending?role=&status=` | 待办列表（非管理员只能看自己的角色） |
| GET | `/api/v1/runs?status=&limit=` | 运行记录 |
| GET | `/api/v1/runs/{run_id}` | 单次审查全景（含待办与审计链） |
| POST | `/api/v1/runs/{run_id}/decide` | 审批（`decision` + `actor` + `note`）；跨环节提交返回 409 |
| GET | `/api/v1/runs/{run_id}/events` | SSE：审计链事件流（游标增量，不丢事件） |
| GET/POST | `/api/v1/proposals`、`/api/v1/proposals/{id}/review` | 规则提案查询 / 审批（主管及以上） |
| GET | `/api/v1/rules` | 规则库快照 |
| GET | `/api/v1/metrics` | 指标 |
| POST | `/api/v1/recover` | 启动补偿（仅 admin；重启后重新通知） |
| GET | `/api/v1/diagnostics` | 详细诊断（仅 admin）：就绪度 / 僵尸审批占用 / 日志轮转 / 配置问题 |
| POST | `/api/v1/maintenance` | 维护动作（仅 admin）：释放过期占用、清理过期令牌、轮转日志 |
| GET | `/health` | 存活探针（轻量、无副作用、不触发编排器编译） |

**curl 示例**：

```bash
# 提交合同
curl -s -X POST http://127.0.0.1:8790/api/v1/contracts \
  -H "X-Auth-Token: local-dev-token" -H "X-Role: specialist" \
  -H "Content-Type: application/json" \
  -d '{"text":"技术服务合同\n第二条 乙方违反保密义务的，违约金为合同总额的 50%。"}'

# 专员确认（把 run_id 换成上一步返回值）
curl -s -X POST http://127.0.0.1:8790/api/v1/runs/<run_id>/decide \
  -H "X-Auth-Token: local-dev-token" -H "X-Role: specialist" \
  -H "Content-Type: application/json" \
  -d '{"decision":"confirm","actor":"specialist-li","note":"确认"}'

# 主管签署
curl -s -X POST http://127.0.0.1:8790/api/v1/runs/<run_id>/decide \
  -H "X-Auth-Token: local-dev-token" -H "X-Role: supervisor" \
  -H "Content-Type: application/json" \
  -d '{"decision":"approve","actor":"supervisor-zhang","note":"同意归档"}'
```

**幂等与并发**：同一 run 的审批只有一个请求能生效；重复提交得到 HTTP 409 与明确提示。

**服务与端口**：能力服务 8770、Mock 8780、网关 8790；日志在 `.runtime\logs\`。

**常见问题**：

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面打不开 | 服务未启动或被回收 | 重新执行 `scripts\start-demo.ps1`，确认三个 `健康` |
| 提交后报"工具不存在: parse_contract" | 工作时 MCP 能力服务未在线，编译出的图没有岗位工具 | 先起 8770 再操作（`start-demo.ps1` 已保证顺序） |
| 上传报 415 | 文件类型不支持 | 仅支持 `.pdf/.docx/.txt/.md` |
| 上传后提示未提取到文本 | 扫描件（无 OCR 档位） | 转人工；后续可升级 OCR 档位 |
| 界面中文乱码（仅 PowerShell 控制台） | 控制台编码 | `$OutputEncoding=[Console]::OutputEncoding=[Text.Encoding]::UTF8`；浏览器不受影响 |
| 审批返回 409 | 已被他人处理 / run 已办结 | 刷新待办列表 |

## 7. 每日作业与指标

**每日例行**（可由定时任务主动完成，见 `docs/06-P6主动工作报告.md`）：
系统会扫描收件目录、对按内容哈希判定为"新"的合同主动发起审查，并把结果与待人工环节邮件通知负责人。

**可用指标**（`GET /api/v1/metrics`）：待办总量 / 在办 / 办结、等待人工的 run 数、决策分布、
驳回原因样本、规则表指纹、法规库条数。

**质量口径**（来自 25 份评测集，见 `docs/10-P7评测与交付报告.md`）：

| 指标 | 结果 |
|---|---|
| 风险召回 | 1.00（0 漏报 / 28 条预埋风险） |
| 误报 | 0 处（54 条干净条款） |
| 等级一致性 | 1.00 |
| 合同类型识别 | 0.96 |
| 表格抽取（11 例） | 单元格正确率 100% |
| 人工介入率 | 0.76 |

> 口径纪律：判定与表格是**两列独立指标**，不合并成单一"准确率"。

> 配置样例见项目根 `.env.enterprise.example`；对接细节见 `docs/13-企业系统对接契约.md`。

| 法规检索 | 关键词 + 2-gram（召回 1.00） | 二期接入向量 + 重排（PG 侧表已预留），指标与一期分开报告 |
| 规则治理 | 提案 → 主管审批 → 版本化写入；冲突强制裁决 | 按企业内部规则评审流程扩展审批层级与生效范围 |
| 合规责任 | 报告含"仅供参考"声明，`high`/`mid` 必须人工签核；**决策与等待环节强绑定**（跨环节审批被拒） | 与企业合规制度对齐：审批留痕、可追溯、责任到人 |

| 运维可观测 | `/health`（轻量存活）、`/api/v1/diagnostics`（就绪度/僵尸占用/日志轮转/连接器配置/配置问题）、`/api/v1/maintenance`（自愈动作） | 接入企业监控告警；按需扩展指标导出 |

**当前一句话结论**：业务闭环、工程质量、**外部系统对接路径**都已就绪，

剩余 PG 部署、OCR 档位、企业 SSO 三项按贵司环境逐项补齐，架构上无需推倒重来。
