# 演示剧本 · 合规官「小合」

> 用途：面试/评审现场按此顺序演示，每一步都有对应命令与可验证输出。
> 前置：本机 PowerShell；已跑过一次 `scripts/d0/install-runtime.ps1` 与 `scripts/deploy-runtime.ps1 -EnableMcp`。

---

## 0. 一页话术（30 秒）

> 这是一个岗位化的合规数字员工：合同进来 → 自动解析条款（含表格）→ 检索法条 → 双通道标注风险 →
> 低风险自动出报告，中高风险转人工签核（专员初审 + 主管复核）→ 结果归档并留下完整证据链；
> 人工驳回的原因不会被直接写成规则，而是生成"规则提案"，经主管批准后版本化进规则库，下次同类条款自动命中。
> 它还会自己巡检收件目录、主动发起审查，并在发现材料缺失时自己安排跟进任务。

## 2. 低风险：全自动办结（20 秒）

```powershell
# 起服务
Start-Process .\.runtime\venv\Scripts\python.exe -ArgumentList "mcp_server\compliance_mcp_server.py"
Start-Process .\.runtime\venv\Scripts\python.exe -ArgumentList "gateway\app.py"
Start-Sleep 4

# 提交一份干净合同（网关接口，带认证与角色）
$body = '{"text":"技术服务合同\n第一条 甲方委托乙方提供运维服务，期限一年。\n第二条 甲方在验收合格后 30 日内支付服务费。\n第三条 双方按约定交付，验收标准以附件一为准。"}'
Invoke-RestMethod -Uri http://127.0.0.1:8790/api/v1/contracts -Method Post -ContentType application/json `
  -Headers @{'X-Auth-Token'='local-dev-token';'X-Role'='specialist'} -Body $body | ConvertTo-Json -Depth 4
```

看点：返回 `status=completed`、`risk_level=low`、`paused=null` —— **没有惊动任何人**。

## 3. 中风险：两个人签核（40 秒）

```powershell
# 提交含"违约金 50%"条款的合同
$mid = '{"text":"技术服务合同\n第一条 甲方委托乙方提供运维服务。\n第二条 乙方违反保密义务的，违约金为合同总额的 50%。\n第三条 甲方在验收合格后 30 日内支付服务费。"}'
$r = Invoke-RestMethod -Uri http://127.0.0.1:8790/api/v1/contracts -Method Post -ContentType application/json `
  -Headers @{'X-Auth-Token'='local-dev-token';'X-Role'='specialist'} -Body $mid
$r | ConvertTo-Json -Depth 4      # 记下 run_id 与 paused.role=specialist

# 看专员待办
Invoke-RestMethod -Uri "http://127.0.0.1:8790/api/v1/pending?role=specialist" `
  -Headers @{'X-Auth-Token'='local-dev-token';'X-Role'='specialist'} | ConvertTo-Json -Depth 3

# 专员确认
$rid = $r.run_id
$d1 = '{"decision":"confirm","actor":"specialist-li","note":"中风险确认"}'
Invoke-RestMethod -Uri "http://127.0.0.1:8790/api/v1/runs/$rid/decide" -Method Post -ContentType application/json `
  -Headers @{'X-Auth-Token'='local-dev-token';'X-Role'='specialist'} -Body $d1 | ConvertTo-Json -Depth 3

# 主管签署
$d2 = '{"decision":"approve","actor":"supervisor-zhang","note":"同意归档"}'
Invoke-RestMethod -Uri "http://127.0.0.1:8790/api/v1/runs/$rid/decide" -Method Post -ContentType application/json `
  -Headers @{'X-Auth-Token'='local-dev-token';'X-Role'='supervisor'} -Body $d2 | ConvertTo-Json -Depth 3
```

看点：专员确认后**必须**由主管签署才归档；两次决策都写进审计链。

## 9. 常见追问与回答要点

| 追问 | 回答要点 |
|---|---|
| 为什么不用框架的 checkpoint 恢复？ | 实测框架线程池恢复路径在跨进程场景下 run 记录会停滞；本项目统一走同步恢复 + 原子抢占，G3/G6 有证据 |
| 为什么人工通知不靠 run_id 人肉回填？ | 框架只发文本通知；本项目建了统一待办表，服务端用待办里的 run_id 恢复，并支持重启后补发通知 |
| 规则会不会被乱改？ | 驳回只生成提案；同模式异等级强制人工裁决；批准才版本化写入；无引用不允许入库 |
| 为什么不直接上向量检索？ | 一期用关键词 + 2-gram 达到召回 1.0；向量与重排是二期，且指标必须与一期分开报告 |
| 表格为什么单列指标？ | 表格承载价款/比例/期限等实质性内容，混进文本指标会掩盖问题 |
| 为什么不做 OCR？ | 本机无管理员权限，完整 OCR 体积大且需 VC++ 运行库；已定档"无 OCR 模式"，扫描件标低置信度走人工，升级只改一处依赖 |
