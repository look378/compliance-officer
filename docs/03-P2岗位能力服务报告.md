## 1. 本阶段交付内容

### 1.1 岗位能力服务（15 个 MCP 工具）

服务从 P1 的 4 个工具扩展到 15 个，按职责分层：

| 类别 | 工具 | 说明 |
|---|---|---|
| 文档 | `parse_contract` | PDF/Word/文本解析 → 条款列表 + Markdown 表格 + 置信度 + 告警 |
| 文档 | `extract_tables` | 表格抽取（Markdown，保留列头与行列结构；未抽到表格显式说明原因） |
| 检索 | `search_regulations` | 法规检索（关键词 + 2-gram，带区分度过滤） |
| 判定 | `annotate_clause` | 单条条款规则标注（含规则版本与法条引用） |
| 判定 | `annotate_document` | 整篇标注 + 汇总分级（进入人工审批前的标准入口） |
| 报告 | `generate_report` | 报告生成（Markdown + PDF，含执行摘要/风险定位/建议/依据/审核链/声明） |
| 规则 | `propose_rule` | 由驳回原因生成提案（三层去重 + 冲突提示） |
| 规则 | `list_rule_proposals` / `approve_rule_proposal` / `reject_rule_proposal` | 提案查询与审批（版本化写入） |
| 流程 | `record_decision` / `list_pending` / `list_audit` | 人工决策审计、统一待办、证据链查询 |
| 流程 | `metrics` | 指标快照（待办/人审率/决策分布/驳回原因样本/版本指纹） |
| 自描述 | `service_info` | 工具清单、规则与法规版本指纹、OCR 档位、能力通道说明 |

**关键验证**：框架侧把这 15 个工具全部注册为 `mcp__compliance__*`，
主 Agent 可用工具数 36 → **51**（`docs/evidence/d0-g4-mcp.json`）。

## 2. 本阶段发现并修正的真实问题（自检价值）

这一节是本报告最重要的部分：下列问题都是**自检/测试真实抓到**的，不是事后补写的。

| # | 问题 | 根因 | 处置 |
|---|---|---|---|
| 1 | 模块内项目根路径算错一层（`parents[2]` 指向项目外），规则表与法规库读成 0 条 | 文件位于 `<project>/mcp_server/`，应为 `parents[1]` | 修正并加入静态自检（数量/来源校验） |
| 2 | 检索把"毫不相关的查询"也判为命中 | 中文 2-gram 词面匹配噪声大（`字符`↔`字符串`） | 引入 **df 过滤**（覆盖 >60% 条目的 token 视为无区分度）+ **最少 2 个有效 token 重合**；空检索显式声明 |
| 3 | 规则去重漏掉"同义不同写法" | 中文正则的写法差异让 difflib 相似度偏低（`最终解释权` vs `最终解释权归.{0,4}方所有` 仅 0.5，低于 0.85 阈值） | 增加**包含关系层**（最长公共字面核心 + 覆盖率约束） |
| 4 | 包含判定把"共享前缀"误判为同一规则 | 首版只要求公共核心 ≥4 字，`自动续约` 与 `自动续约…无需通知` 被误并 | 增加**覆盖率 ≥60%** 约束；并补一条单元测试固定该边界 |
| 5 | 同模式异等级的提案被"自动转修订"吸收 | 去重判定优先于冲突判定 | **冲突优先级提升到去重之前**，生成 `kind=conflict` 的待裁决提案，且**禁止写入** |
| 6 | 缺法条引用的提案仍能写成 active 规则 | 写入关口未校验引用 | 在 `approve` 处加硬校验：无 `regulation_ref` 一律拒绝 |
| 7 | 规则表出现"磁盘已还原、内存仍旧值"的不一致 | 规则读取有进程内缓存 | 去掉缓存（YAML 很小），并在注释中说明原因 |
| 8 | YAML 日期类型漂移（读进来 `date`、写回去 `str`） | PyYAML 自动解析日期 | 写回时统一字符串化 |
| 9 | 自检自身修改了既有规则语义（RR-003 等级被覆盖） | 自检批准了一个"修订提案" | 自检改为：动规则表的用例只针对**自建规则**；并对规则表做**快照 + 还原 + 指纹比对**，不通过即判 FAIL |
| 10 | 自检不可重复运行（残留待办/审计导致断言失败） | 使用固定 run_id，且失败时未清理 | 改用唯一 run_id + 结束清理；规则快照还原纳入判定 |
| 11 | 重构后直接运行服务脚本时包导入失败 | `sys.path[0]` 是 `mcp_server/`，包内绝对导入失效 | 脚本入口自举项目根路径；启动方式同时支持脚本与 `-m` |
| 12 | 短条款（已识别条款号）被判为低置信度 | 置信度用"文本长度"当门槛 | 改为**只在完全没有可用文本时**压到最低档；短条款按"有无条款号"判定 |

| 故障 | 断言 | 结果 |
|---|---|---|

| `empty` | 返回结构合法但内容为空，调用方可判定 | PASS |

## 4. 对后续阶段的输入

### P3（主流程编排）

1. 用 `tool` 节点直接调用本阶段的 MCP 工具（`parse_contract` → `search_regulations` → `annotate_document` → `generate_report`），不要把确定性环节交给模型自由裁量。
2. 严格遵守 G2 得出的**拓扑纪律**：一个节点要么静态出边、要么条件边。
3. 风险分级使用离散字符串；人工节点决策字段与条件边 mapping 一一对应。
4. 报告生成后调用 `record_decision` 留痕，形成证据链。

### P4（人工闭环）

1. 待办队列已就绪（`queue_store.create_todo/claim_todo/complete_todo`，含**原子领取**）。
2. 启动扫描补发通知已就绪（`queue_store.notify_pending_on_startup`）。
3. run 层互斥用 `runtime_store.claim_run`（G6 已验证）；恢复走**同步路径**，不用框架线程池恢复。

### P5（规则提案）

1. 提案链路已就绪：`propose_rule` → `approve_rule_proposal` / `reject_rule_proposal`。
2. 去重（精确/包含/相似）与冲突（同模式异等级）均已实现并有测试；**禁止静默覆盖**已落到写入关口。
3. 审计复用条目内联字段 + `compliance_audit` 事件表，不单独建历史表。

### P7（评测）

1. 当前评测集偏小（7 条），需扩到 ≥20 份合同并**逐项报告**命中/漏报/误报。
2. 表格抽取必须作为**独立指标**，不与文本判定混报。
3. 规则表与法规库的版本指纹（digest）应写入报告，保证"结论可复现"。
