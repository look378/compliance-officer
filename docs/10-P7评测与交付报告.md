- 评测集：`data/eval/eval_contracts.json`，覆盖劳动用工/采购/租赁/金融销售/数据合规/合同通则 6 类，
  其中 11 份含表格、19 份含预埋风险、5 份为干净对照样本。
- 表格指标**单独成列**：表格承载价款、比例、期限等实质性内容，混进文本指标会掩盖问题。

### 1.1 本阶段修正的两处（都是评测侧问题，不是系统缺陷）

1. **评测集标注不完整**：`EV-020` 含"投保人可在犹豫期内无条件解除本合同"，
   系统命中 `RR-004` 是**正确**行为，但期望清单漏了该规则 → 修正标注。
2. **类型识别器过于粗糙**：单条款合同里类型专属词只有一个，通用词（甲方/乙方）反而更多，
   导致 5 份合同被误判为"合同通则" → 改为"专属词加权 + 标题信号 + 通用词兜底"，
   并把判定依据（得分）写进证据，可复算。

## 2. 轻量网关（`gateway/app.py`）

| 路由 | 说明 | 验证 |
|---|---|---|
| `POST /api/v1/contracts` | 提交合同（走两段式） | 低风险→completed、中风险→paused 且带待办角色 |
| `GET /api/v1/pending` | 待办（按角色过滤；非管理员只能看自己角色） | PASS |
| `GET /api/v1/runs` `/{run_id}` | run 列表与单 run 全景（含命中规则/待办/审计链） | PASS |
| `POST /api/v1/runs/{run_id}/decide` | 审批（原子认领） | 并发 4 → 接受 1、**409** 3 |
| `POST /api/v1/recover` | 启动补偿（仅 admin） | PASS |
| `GET/POST /api/v1/proposals[/{id}/review]` | 规则提案与审批 | PASS |
| `GET /api/v1/metrics` | 指标 | PASS |
| `GET /api/v1/runs/{run_id}/events` | SSE：审计链事件流 | 收到 `audit/status/done` |
| `GET /health` | 健康检查（含能力服务联通状态） | PASS |

**RBAC 实测**：无 token → `401`；专员调用 admin 接口 → `403`；admin → `200`。

> 说明：框架的流式输出硬绑定终端通道（D0 实读），因此网关的"进度推送"采用**审计链事件流**，
> 与证据链同源，不侵入框架输出通道。
